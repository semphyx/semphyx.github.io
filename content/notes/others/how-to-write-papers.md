草案 v0.5(2026-10-06)。学会の執筆要項・投稿の手引き・査読基準、図表作成ガイド、英語論文執筆書など(末尾の英語参考文献を含む)の要点をもとに、学部の学生向けに再構成したものです。例文は「モータ駆動回路実験」を題材にしています。

卒業論文・学会論文の書き方(第1〜10章)と参考文献です。実験レポートの書き方は別冊にあります。

## はじめに

第1〜4章(文章、数値・単位、図表、引用と倫理)は、実験レポートと論文に共通する内容です。第5章以降では、論文に特有のことを書きます。

電気電子分野で最も多くの論文が投稿される IEEE の論文誌と、分野を問わず読まれる総合誌 Nature の投稿規定・書式ガイド(B6、B10、B11)を手本にして、具体的な書き方を示します。二つの書式は目指すところが違うので、違いを知っておくと、どの投稿先にも対応しやすくなります。

> **注意**:投稿規定は改訂されます。数値(語数・図の数など)は 2026-10-03 時点で各ガイドを確認した値です。投稿するときは、必ず投稿先の最新の規定を読むこと。

## 第1章 文章の書き方

### 1.1 基本の原則

| 原則 | 内容 |
|---|---|
| 一文を短く | 一文に一つの内容(一文一義)。目安は60字以内。長い文は分ける |
| 結論を先に | 段落の最初の文で、その段落の主張を述べる |
| 曖昧な語を使わない | 「かなり」「少し」「いろいろ」「約〜くらい」ではなく、数値で書く |
| 主語を明らかに | 何が、何をしたのかがわかるように書く |
| 用語を統一する | 同じものを別の言葉で呼ばない(「電流リプル」「電流の波打ち」「リップル」を混在させない) |
| 略語は初出で定義する | 「パルス幅変調(PWM:Pulse Width Modulation、以下PWM)」 |
| 文体を統一する | レポート・論文は「である」調で書く |
| 削る | 書けば書くほど誤りが増える。不要な語・文・段落を削る |

### 1.2 よくある悪い書き方

| 悪い例 | 問題点 | 改善例 |
|---|---|---|
| 電流がかなり大きくなった。 | 「かなり」が曖昧 | 電流は 0.5 A から 1.8 A に増加した。 |
| 周波数を上げるとリプルが小さくなることがわかったが、これはインダクタンスがあるためであり、周波数が高いと電流が変化する時間が短いからで、… | 一文が長く、因果関係がたどれない | 周波数を上げると、リプルは小さくなった。これは、1周期の間に電流が変化できる時間が短くなるためである。電流の変化の速さは、インダクタンスによって制限される。 |
| 興味深い結果が得られた。 | 何が興味深いのか不明 | 拘束時と回転時で、比例制御の定常偏差が 3 倍異なった。 |
| 〜と思う。〜な気がする。 | 根拠が示されていない | 〜と考えられる(理由:…)。 |
| 実験はうまくいった。 | 評価の基準が不明 | 測定値は計算値と 5% 以内で一致した。 |
| リプルは十分に小さかった。 | 「十分」の基準と、比べる相手がない | 20 kHz でリプル幅は平均電流の約 2% であった。 |
| PWM周波数とデッドタイムを変えた。これにより平均電圧が下がった。 | 「これ」が周波数とデッドタイムのどちらを指すかわからない | デッドタイムを 5 μs にしたとき、平均電圧が下がった。 |

「大きい」「高い」「良い」「十分」「適切」「ほぼ」「効果的」「高性能」も、「かなり」と同じく曖昧な語です。数値、条件、比較する相手のどれが欠けているかを考え、補います。

### 1.3 事実と推測の書き分け

| 種類 | 文末の例 |
|---|---|
| 事実(測定したこと) | 〜であった。〜を示した。〜した。 |
| 確かな解釈 | 〜である。〜による。 |
| 推測(根拠がある) | 〜と考えられる。〜と推定される。 |
| 可能性 | 〜の可能性がある。 |

一つの文の中で、事実と推測を混ぜません。

レポートや論文に書く内容は、事実・解釈・主張の三つに分けて考えます。

| 種類 | 内容 | 例(モータ駆動回路実験) |
|---|---|---|
| 事実 | 測定・計算で得られたこと。条件と数値で言える | リプル幅は 2 kHz で 0.36 A、20 kHz で 0.041 A であった。 |
| 解釈 | 事実がなぜ生じたかの説明。根拠が必要で、推測を含む | 1周期の間に電流が変化できる時間が短くなるためと考えられる。 |
| 主張 | 事実と解釈をもとに、読み手に伝えたい結論。適用できる条件を伴う | 拘束モータでは、PWM周波数を上げることでリプル幅を抑えられる。 |

事実から主張までの間に、解釈が入ります。解釈が抜けると、主張に根拠がないように見えます。事実だけを並べても、主張は伝わりません。

### 1.4 推敲

- 書き終えたら、時間を置いてから読み直す。
- 大きいところから順に見直す。(1) 読み手と中心の主張、(2) 全体の構成、(3) 論理(目的・方法・結果・考察・結論が対応しているか)、(4) 証拠(主張を支える数値や図があるか)、(5) 文章、の順。文章を整えてから構成の誤りに気づくのは無駄が大きい。
- 紙に印刷して読む。声に出して読む。
- 他の人に読んでもらう(読み手の立場で読める)。
- 目的と結論が対応しているか、図表番号と本文の引用が一致しているかを確認する。

### 1.5 不足を推測で補わない

書いている途中で、数値・条件・根拠・出典・原因が足りないことに気づくことがあります。わからないことを、もっともらしい推測で埋めてはいけません。存在しない数値や文献を作ることは、捏造にあたります(4.3節)。

下書きの段階では、不足している箇所に印を付けておき、提出前に測定ノート・データ・文献で確かめて解消します。

| 印 | 使う場面 |
|---|---|
| 【要確認】 | 値や事実が正しいか確かめられていない |
| 【数値未提示】 | 数値で言うべきところに、数値がない |
| 【根拠不足】 | 主張や解釈を支えるデータ・計算がない |
| 【引用文献が必要】 | 出典が必要な内容に、出典がない |
| 【因果関係未確認】 | 原因だと書いたが、他の可能性を除いていない |
| 【用語定義が必要】 | 初出の用語や記号を定義していない |

- 印は、提出するレポートには残さない。解消できなかった箇所は、わからないことを事実として書く(例:「差の原因は、本実験の範囲では特定できなかった」)。
- 解消できない主張は、弱めるか、削る。

### 1.6 論理のつながりと飛躍

レポートの論理は、次の連鎖で成り立ちます。前の項目から次の項目へ、自然につながっているかを確かめます。

目的(何を明らかにするか)→ 方法(なぜその測り方か)→ 結果(何が得られたか)→ 考察(なぜそうなったか)→ 結論(目的への答え、適用できる範囲)

| 飛躍 | 悪い例 | 直し方 |
|---|---|---|
| 相関を因果と断定する | 周波数を上げたらリプルが減った。したがって、リプルの原因は周波数だけである | 他の条件(電源電圧、デューティ比)を変えていないことを示したうえで、「この条件では」と限定する |
| 一部の条件を全条件に広げる | 拘束モータでリプルを測った。したがって、回転中も同じである | 拘束時の結果であることを明記し、回転時は未確認であると書く |
| 比較する相手が違う | 計算値は電源 6 V、測定値は電源 12 V のときのものである | 条件をそろえて比べる。そろえられないときは、違いを明記する |
| 結論に対応する結果がない | 結論に「効率が高い」とあるが、効率を測っていない | 結論には、結果で示したことだけを書く |
| 手段の選択理由がない | PI制御を使った(なぜかの説明がない) | 目的に対して、なぜその方法を選んだかを一文で書く |

結論は、目的に答える内容に絞ります。結論に、結果や考察にない内容を足すと、飛躍になります。

### 1.7 略語の書き方

略語(FEM、RTOS など)は、初出で正式名称を書いてから使います。2 回目以降は略語だけでかまいません。

| 書き方 | 例 |
|---|---|
| 日本語名(英語の正式名称、略語) | 有限要素法(Finite Element Method、FEM) |
| 英語の正式名称(略語) | Real-Time Operating System(RTOS) |
| 略語(日本語名または正式名称) | FEM(有限要素法) |

- 一般用語(AI、PC、USB、CPU、LED、IC、DC、CSV、PDF、ISO、IEEE、JIS など)、単位、元素記号、化学式は、正式名称を書かなくてよい。迷ったら書く。読み手にとって一般的でない語は、一般用語として扱わない。
- 要旨、見出し、図表のキャプションなど、本文から切り離して読まれる箇所では、略語を使うなら、その箇所でも正式名称を書く。
- 同じ概念を、略語と正式名称、別の略語で書き分けない。一度決めた略語は、全体で同じものを使う。
- 型番・部品番号・ラベル(例:RP2350、B1、Q1)は略語ではないが、初出で何を指すかを本文で説明する。
- 略語が多いときは、冒頭または末尾に略語の一覧(略語、正式名称、意味)を置いてよい。

## 第2章 数値・単位・式

### 2.1 単位

- SI単位を使う。
- 数値と単位の間には半角スペースを入れる(12 V、20 kHz、25 mΩ)。ただし % と °(角度)は空けない(5%、90°)。これは和文の慣習に合わせた規則で、SI の表記規則では % の前にも空白を入れる。どちらを使ってもよいが、1 通の報告書の中では統一する。
- 単位記号の大文字・小文字を正しく書く(kHz、mΩ:ミリオーム、MΩ:メガオーム)。
- マイクロは μ と書く。u で代用しない。
- 表やグラフの軸では、量と単位を「電流 [A]」または「電流 (A)」の形で書く。どちらかに統一する。
- 接頭語は単位記号に直接つけ、一度に一つだけ使う(μμF、nkg は不可)。単位の積は N·m のように中点か空白、商は m/s か m·s⁻¹ と書く。
- 本文中の「12 V」のように数値の後ろに書く単位には、括弧をつけない。式の中などで単位と量の記号を読み違えるおそれがあるときに限り、$L$ [mH] のように角括弧で囲む。

### 2.2 有効数字

- 測定器の分解能と測定のばらつきから、意味のある桁までを書く。
- 計算結果の桁数を、元の測定値の精度より多くしない。電卓の表示をそのまま写さない。
- ディジタル表示の桁数は、測定器の確度を表さない。表示が 100.0012 kHz でも、確度が ±0.1% なら 100.0 kHz と書き、残りの桁は捨てる。確度は測定器の仕様書で確認する。
- 「10」と「10.0」は別の数値である。最も右の桁が、誤差を含む桁として適切かを確かめる。
- 周波数や電圧は、信号発生器で設定した値を信用せず、オシロスコープなどで実際の値を確認して目標値に合わせる。

| 悪い例 | 良い例 | 理由 |
|---|---|---|
| $R = 1.723529$ Ω | $R = 1.72$ Ω | 電圧・電流が3桁の測定なら、結果も3桁程度 |
| 誤差は 4.8213% | 誤差は 4.8% | 誤差の値は1〜2桁で十分 |

### 2.3 誤差の示し方

- 理論値との比較には相対誤差を使う:$(\text{測定値} - \text{理論値}) / \text{理論値} \times 100$ %
- 繰り返し測定した場合は、平均値とばらつき(標準偏差など)を示す。
- 誤差の原因を考察するときは、各原因がどの程度の大きさの誤差を生むかを見積もる。
- 標準偏差と平均の標準誤差を区別する。標準偏差 $s$ は 1 回の測定のばらつきを表し、測定回数 $n$ を増やしても小さくならない。平均値のばらつきは標準誤差 $s/\sqrt{n}$ で表し、$n$ を増やすと小さくなる。何を示しているかを、報告書に書く。
- 測定器の分解能・確度に由来する不確かさも書く。表示の最小桁が $\delta$ なら、その寄与の標準不確かさは約 $\delta/(2\sqrt{3})$ である。繰り返しのばらつきと独立に扱えるときは、二乗和の平方根で合成する。
- グラフの誤差棒は、何を表すかを凡例か図の説明に書く(標準偏差、標準誤差、測定器の確度など)。
- 理論値が 0 付近のときは、相対誤差を使わない。絶対差、またはフルスケールなどの基準量に対する割合で示す。

例:電圧を 5 回測り、4.98、5.02、5.01、4.97、5.02 V を得た(電圧計の最小桁は 0.01 V、理論値は 5.00 V)。

| 量 | 値 | 意味 |
|---|---|---|
| 平均 | 5.00 V | 5 回の平均 |
| 標準偏差 $s$ | 0.023 V | 1 回の測定のばらつき |
| 標準誤差 $s/\sqrt{5}$ | 0.010 V | 平均値のばらつき |
| 分解能の寄与 $0.01/(2\sqrt{3})$ | 0.003 V | 測定器の最小桁 |
| 合成した標準不確かさ | 0.011 V | $\sqrt{0.010^2 + 0.003^2}$ |

結果は「$5.00 \pm 0.01$ V(標準不確かさ)」と書けます。理論値が 0 V で測定値が 0.012 V のときは、相対誤差は定義できません。「差は 12 mV で、フルスケール 5 V の 0.24%」のように書きます。

### 2.4 式と記号

- 量を表す記号はイタリック($V$、$I$、$R$)、単位・関数名・数字は立体(V、A、sin、2)で書く。
- 添字が変数ならイタリック($V_i$)、語の略なら立体($V_\mathrm{dc}$)とする(分野によっては区別しない)。
- 独立した行に書いた式には番号を付ける(式(1))。本文で参照するときは「式(1)より」と書く。
- 式に出てくる記号は、すべて初出で定義する(「ここで $L$ は電機子インダクタンスである」)。
- 式の導出に飛躍がないようにする。読み手が自分で式を導けることが求められる。

## 第3章 図表の作り方

### 3.1 基本の考え方

図表は、主張を伝えるための道具です。一つの図で言いたいことは一つに絞り、それを伝えるのに不要な要素は削ります。

- グラフは、プロット領域(軸)の四辺を黒い線で囲む。図全体(画像の外周)は枠で囲まない。回路図・写真・オシロスコープの画像など、軸のない図にも枠は付けない。表にも枠を付けない(3.5節)。
- 目盛りは内向きにし、背景の格子(グリッド)は付けない。
- 測定値は**中抜きの丸(○)**で描き、計算値は線で描く。
- 図のタイトル(キャプション)は図の下、表のタイトルは表の上に書く。
- 図表には通し番号を付け(図 1、表 1)、本文で必ず引用する。
- キャプションだけで図の内容がわかるように書く(条件も書く)。

図表は、作る前に、次の項目をメモしておきます。決められない図表は、載せる理由がありません。

| 項目 | 例(PWM周波数とリプル幅の図) |
|---|---|
| 目的 | 測定値が計算値と合っているかを確かめる |
| 伝える主張 | リプル幅はPWM周波数に反比例し、計算値と一致する |
| 必要なデータ | 各周波数のリプル幅の測定値と計算値 |
| 軸と比較対象 | 横軸はPWM周波数、縦軸はリプル幅。測定値(点)と計算値(線)を比べる |
| 見てほしい点 | 点が直線の上にのること、一致の程度 |
| 本文での引用箇所 | 結果の章で引用し、考察で相対誤差を述べる |

### 3.2 本文での図表の引用

「本文で引用する」とは、文の中で図表を主語や目的語として名指しし、その図表から何がわかるかを述べることです。

文末に「(図 3)」「(Fig. 3)」とかっこ書きを添えるだけの書き方は、引用として認めません。生成AIが出力する文章によく見られる書き方ですが、次の問題があります。

- 読み手は、図のどこを見て何を確かめればよいのかわからない。
- 文の内容が本当にその図から言えるのか、書き手が確かめたかどうかがわからない。図と関係のない文に番号だけが付いていることもある。
- 図の番号が変わったときに、どの文を直せばよいかがわかりにくい。

| 悪い例(引用にならない) | 良い例 |
|---|---|
| リプル幅は周波数が高いほど小さくなった(図 3)。 | 図 3に示すように、リプル幅はPWM周波数にほぼ反比例し、2 kHz の 0.36 A から 20 kHz の 0.041 A まで減少した。 |
| 比例ゲインを上げると定常偏差が減った(Fig. 4)(表 1)。 | 表 1に比例ゲインと定常偏差の関係をまとめた。$K_p$ を 3 V/A から 12 V/A に上げると、定常偏差は 36% から 12% に減少した。 |

学会論文などで「(Fig. 3)」のような書き方が使われることはありますが、それは本文の別の箇所で図の内容をきちんと説明したうえでの補足です。まずは、すべての図表について「図○に示すように〜」「表○から〜がわかる」と文章で説明できるようにします。

### 3.3 グラフ

| 項目 | ルール |
|---|---|
| 軸 | すべての軸に量と単位を書く。目盛りの数字の桁数をそろえる |
| 測定値と理論値 | 測定値は点(マーカー)、理論値・計算値は線で示して区別する |
| 線と点 | データの線は、軸や枠の線より太くする。色だけでなく線の種類・マーカーの形でも区別する |
| 文字 | 印刷したときに読める大きさにする(本文と同じ程度) |
| 凡例 | 複数のデータがあるときは凡例を付ける。データに重ならない位置に置く |
| 軸の範囲 | データが図の大部分を占めるようにする。無意味な余白を作らない |
| 両対数・片対数 | 反比例や指数関係を示すときは、対数軸を使うと直線になって比較しやすい |
| 複数のパネル | (a)、(b) のラベルを左上に付け、大きさと位置をそろえる |

### 3.4 色の使い方

- 色の数を絞る。文字や矢印は黒か灰色にする。
- 赤と緑の組み合わせは、色覚の多様性により区別しにくい人がいる(日本人男性の約5%)。明るさの差や、線の種類・マーカーの形でも区別できるようにする。
- 白黒で印刷しても区別できるかを確認する。

### 3.5 表

- 縦の罫線は使わず、横の罫線だけを細く引く。
- 数値の桁数をそろえる。整数は右揃え、小数は小数点の位置でそろえる。文字は左揃えにする。すべてを中央揃えにしない。
- 単位は列の見出しに書き、各セルに繰り返さない。

### 3.6 オシロスコープの波形

- 保存した画像を貼るときは、時間軸と電圧軸の1目盛りの大きさがわかるようにする。
- どのチャネルが何の信号かを、図中またはキャプションに書く。
- 見るべき箇所(デッドタイム、リプル幅など)を矢印などで示す。

### 3.7 悪い図と良い図の見本

モータ駆動回路実験を題材にした3つの見本があります(データは説明用の架空の値)。

**見本1:測定値と計算値の比較**

| 悪い例の問題点 | 良い例での直し方 |
|---|---|
| 軸が「f」「ripple」だけで、量の名前も単位もない | 「PWM周波数 [kHz]」「電流リプル幅 [A]」と量と単位を書いた |
| 目盛りが 2500, 5000, … と桁が多く読みにくい | 単位を kHz にして 2, 5, 10, 20 とした |
| 測定値も計算値も折れ線で、どれが測った点かわからない | 測定値は○(点)、計算値は線にした |
| 計算値を測定した4点でしか求めていないため、折れ線になる | 計算値は細かい間隔で求め、なめらかな曲線にした |
| 凡例が「data1」「data2」で、何のデータかわからない。凡例がデータの真ん中にある | 凡例に「測定値」「計算値(式(3))」と書き、データのない場所に置いた |
| 反比例の関係が曲線になり、理論と合っているか判断しにくい | 両対数軸にして直線で比較できるようにした |
| 図の上に「グラフ1」という中身のないタイトルがある | 図の中のタイトルは削り、図の下に内容がわかるキャプションを書いた |
| 赤と緑の線で区別している。太い格子線と色付きの背景が目立つ | 黒一色で、点と線の形で区別した。格子と背景を削った |
| 目盛りや軸の文字が小さすぎる | 本文と同じくらいの大きさにした |

**見本2:複数の条件を一つの図に描く**(比例制御における電流のステップ応答)

| 悪い例の問題点 | 良い例での直し方 |
|---|---|
| 赤・緑・黄緑の色だけで区別していて、白黒印刷や色覚の多様性によっては区別できない | 実線・破線・点線で区別した |
| 凡例が図の外にあり、線と凡例を見比べる必要がある | 線の横に直接ラベルを書いた |
| 軸に単位がない(「時間」「電流」) | 「時間 [ms]」「電流 [A]」とした |
| 指令値がないので、定常偏差があることが読み取れない | 指令値 1 A を灰色の線で示した |
| ゲインの単位がない | 「$K_p$ = 12 V/A」と単位を付けた |

**見本3:表**

| 悪い例の問題点 | 良い例での直し方 |
|---|---|
| 表のタイトルが表の下にあり、内容も「結果」だけ | 表の上に、条件がわかるタイトルを書いた |
| 縦横すべてに太い罫線があり、見出しに色が付いている | 横の罫線だけにした(上下は太く、見出しの下は細く) |
| 単位を各セルに書いていて、「ms」の前の空白も不ぞろい | 単位は列の見出しに書いた |
| 桁数がそろっていない(0.3 と 0.41、0.6382 と 0.78) | 有効数字をそろえ、右揃えにして小数点の位置をそろえた |
| 「誤差」が何に対する誤差かわからない | 「定常偏差」(指令値との差)と書いた |

### 3.8 図表チェックリスト

- [ ] その図で言いたいことは一つに絞られているか
- [ ] 図表ごとに、目的・伝える主張・比較対象を決めてから作ったか(3.1節)
- [ ] すべての軸に量と単位があるか
- [ ] 測定値(点)と理論値(線)を区別しているか
- [ ] 文字は印刷して読める大きさか。フォントは統一されているか
- [ ] 色だけに頼らず、白黒でも区別できるか
- [ ] グラフのプロット領域を、四辺の黒い線で囲んだか(図全体は囲まない)
- [ ] 図の中の不要な影・グリッド・装飾を削ったか
- [ ] 図のタイトルは図の下、表のタイトルは表の上にあるか

## 第4章 引用・参考文献と研究倫理

### 4.1 引用のルール

- 他人の文章・図・データ・考えを使うときは、必ず出典を示す。自分の考えと他人の考えを区別できるようにする。
- 他人の文章をそのまま使う場合は、かぎかっこで囲んで引用であることを示し、出典を書く。長く引用しない。
- 他人の図を使う場合は、出典を書く。論文として公表する場合は、著作権者の許可が必要である。

### 4.2 参考文献の書き方

本文中で引用した箇所に番号を付け(〜と報告されている[1])、末尾に番号順に一覧を書きます。書式は指示されたもの(論文なら投稿先の規定)に従い、一つのレポートの中で統一します。

```text
[1] 著者名, "論文の題名," 雑誌名, 巻, 号, pp. 開始頁–終了頁, 発行年.
[2] 著者名, 書名, 第○版, 出版社, 発行年, pp. 頁.
[3] 発行者名, "ページの題名," URL(参照日:2026年10月3日).
```

- 引用した文献と、文献一覧を一致させる(一覧にあるのに本文で引用していない、またはその逆を作らない)。
- Webページより、教科書・論文・データシートなど、確かめられる公刊の資料を優先する。Webページを引用する場合は参照日を書く。

### 4.3 研究倫理

次の行為は、レポートでも論文でも不正行為として扱われます。

| 行為 | 内容 |
|---|---|
| 捏造 | 存在しないデータを作る |
| 改ざん | 都合のよいようにデータを変える、都合の悪いデータを黙って除く |
| 盗用(剽窃) | 他人の文章・データ・考えを、出典を示さずに自分のものとして使う。他人のレポートの写しも含む |
| 二重投稿 | 同じ内容を、別の論文として重ねて発表する |

- 測定に失敗したデータや、予想と合わないデータも、そのまま報告し、考察する。データを除く場合は、その理由を書く。
- 測定値は揺らぐのが普通である。外れた値は、まず再測定や再計算で確かめる。それでも外れる場合に限って除外し、除外したことと理由を必ず注記する。予想外の値は、捨てる対象ではなく考察の対象である。注記つきの除外と、黙って除く改ざんは別の行為である。
- 実験した日付を測定ノートとレポートに書く。書き直して再提出するときは、その日付も加える。
- 共同で実験した場合も、レポートは自分の言葉で書く。
- 相関を因果と断定したり、確かめていない条件にまで結果を広げたり、評価条件を省いて性能を言い切ったりしない(1.6節)。不利な結果や、結果が成り立たない条件も隠さずに書く。
- 企業・共同研究先から得た資料や、未公開のデータを使う場合は、持ち出してよいかを担当教員に確認する。公開されるレポートや論文では、個人名や機密の情報を、「対象の装置」「担当者」のように一般化して書く。数値や名称を、都合よく書き換えてはいけない。

## 第5章 実験レポートと論文の違い

### 5.1 違いの一覧

| | 実験レポート | 論文(卒業論文・学会論文) |
|---|---|---|
| 読み手 | 担当教員(その分野を知っている人) | 同じ分野の研究者(査読者を含む)。卒業論文では、研究室外の教員や後輩も含む |
| 目的 | 実験の内容を理解したことを示す | 新しい知見を他の研究者に伝え、記録に残す |
| 新規性 | 不要 | 必須。「何が新しいか」「従来と何が違うか」を示す |
| 目的の決め方 | テキストで与えられる | 自分で問いを立て、先行研究の中に位置づける |
| 文献の引用 | 教科書・データシート程度 | 関連する研究を調べて引用する。引用の量と質も評価される |
| 構成 | 目的・原理・方法・結果・考察・結論 | 序論・方法・結果・考察・結論。「結果と考察」をまとめる場合も多い |
| 書式 | 授業の指示に従う | 投稿先・大学の規定に従う。規定違反は審査前に返却されることがある |

### 5.2 「実験レポート型」の原稿にしない

論文の書き方の資料では、「条件を変えて測っただけの実験レポート型の原稿は論文として採用されない」と繰り返し述べられています。論文では、結果から「だから何がわかったのか」「それは従来の知見に何を加えるのか」まで書く必要があります。

逆に言えば、実験レポートの考察を「だから何がわかったのか」まで掘り下げる練習を続けていれば、論文を書く力がついていきます。

### 5.3 新規性・有効性・信頼性

論文の審査では、主に次の3点が問われます。

| 観点 | 問われること |
|---|---|
| 新規性 | 従来の研究と何が違うか。誰も示していないことか |
| 有効性 | その結果は、読者(他の研究者・技術者)にとって役に立つか |
| 信頼性 | 根拠と論理の筋道が示され、同じ条件で再現できるか |

そのためには、関連する研究を調べ、何がわかっていて何がわかっていないかを整理し、自分の研究がどこに位置づくかを示す必要があります。自分の寄与と、他人の研究による部分を区別して書きます。

書き始める前に「この論文の主張(中心となる一つのメッセージ)」を一文で決め、それを表題・要旨・序論・結論で一貫させます[B1, B2]。一文で言えないときは、書き始めずに主題を整理します。主題が複数あるときは、上位の主張でまとめる、章を分ける、別の論文に分ける、付録に移す、のいずれかにします。

### 5.4 課題・新規性・有用性・証拠の整理

書き始める前に、次の4つを整理します。以下の例は、7.3節の要旨の骨組みと同じ題材で、数値は説明用の仮のものです。実際の論文では、自分のデータだけを使います。

**課題は「解決すべき状態」で書く**

課題は、手段ではなく、解決すべき状態として書きます。手段を課題にすると、その手段が妥当かどうかを論じられなくなります。

| 悪い例(手段) | 良い例(解決すべき状態) |
|---|---|
| 極零相殺でPIゲインを設計する | 計算の遅れとデューティ比の上限があっても、電流ステップ応答の行き過ぎを抑えられる交差周波数の範囲を、設計者が見積もれるようにする |

課題は、背景(何が使われているか)→現状(何がわかっているか)→望ましい状態→そのギャップ→原因→取り組む課題→対象範囲と対象外、の順に整理すると書きやすくなります。序論の流れ(7.5節)は、この整理を文章にしたものです。

**新規性は「従来との差」と「その根拠」で示す**

「新しい」と書くだけでは、新規性は示せません。次の項目を埋めます。

| 項目 | 例 |
|---|---|
| 既存の技術・研究と、できること | 極零相殺による設計は広く使われ、遅れがなければ応答を設計できる |
| できないこと・限界と、その理由 | 計算の遅れとデューティ比の上限を含めた応答が、定量的に示されていない |
| 今回変えたこと | 遅れと上限を含めて、交差周波数を変えた応答を測定した |
| 従来との違いを示す根拠 | 交差周波数ごとの行き過ぎ(測定値)と、先行研究との比較 |

先行研究を十分に調べていないときは、「初めて」「他にない」と断定しません(9.5節)。

**有用性は「誰の何が、どの条件で、どれだけ」で示す**

| 項目 | 例 |
|---|---|
| 誰のどんな課題か | 低価格のマイコンで電流制御を作る設計者の、ゲイン調整の手間 |
| 何が改善したか | 行き過ぎが小さくなった |
| 改善の量 | 行き過ぎが 15% から 2% 未満になった |
| どの条件で有効か | 交差周波数がPWM周波数の 1/20 以下のとき |
| 比較対象と測定方法 | 交差周波数がPWM周波数の 1/10 のとき。同じ装置のステップ応答 |
| 副作用・限界 | 応答は遅くなる。他の機種や負荷では未確認 |

定性的な結果しかないときは、数値にできる指標(時間、誤差、行き過ぎ、消費電力、コスト、再現性など)を探します。存在しない数値を作ってはいけません(1.5節)。

**主張と証拠の対応表を作る**

主張ごとに、それを支える証拠が十分かを、書き始める前に表で確かめます。

| ID | 主張 | 必要な証拠 | 現在の証拠 | 判定 |
|---|---|---|---|---|
| C1 | 交差周波数がPWM周波数の 1/20 以下なら、行き過ぎが 2% 未満である | 複数の交差周波数でのステップ応答、繰り返し測定 | 測定値はあるが、繰り返し測定がない | 要補強 |
| C2 | この上限は、計算の遅れで説明できる | 遅れを含むモデルの計算値と測定値の比較 | 比較がない | 不足 |

判定は「十分」「要補強」「不足」の三つにします。「要補強」「不足」の主張は、追加の測定をするか、弱めるか、削ります。証拠については、測定方法・条件・比較条件・試料数・ばらつきに問題がないか、結果を一般化しすぎていないか、別の原因がないかも確かめます。

**論理の連鎖を確かめる**

背景→問題→原因→課題→考え方→方法→評価方法→結果→結果からわかること→価値→適用範囲と制約

各項目が前の項目から自然につながっているかを確かめます(飛躍の例は1.6節)。

## 第6章 投稿先の書式を知る:IEEE と Nature

### 6.1 二つの書式の違い

| 項目 | IEEE の論文誌(Transactions など) | Nature(Article) |
|---|---|---|
| 想定する読み手 | 同じ分野の研究者・技術者 | 分野外の研究者を含む幅広い読者 |
| 構成の順番 | 表題 → 要旨 → Index Terms → 序論 → 本文 → 結論 → 付録 → 謝辞 → 参考文献 | 表題 → 要約段落 → 本文 → 参考文献 → 図の説明 → Methods → データ・コードの公開 → 謝辞・資金・著者の貢献・利益相反 |
| 表題 | 具体的で簡潔に。「new」「novel」を使わない | 2行(空白を含め75文字)以内。数字・略語・記号を原則使わない |
| 要旨 | 1段落、150〜250語。式・引用番号・脚注を入れない | 要約段落、200語以内が目安。引用番号を付ける。数値・略語は必要なときだけ |
| キーワード | Index Terms が必須(アルファベット順) | なし |
| 本文の長さ | 論文誌ごとにページ数の上限がある | 6ページの論文で約2,500語＋図表4点が目安 |
| 方法 | 本文の中の章として書く | 本文の後に Methods としてまとめる(3,000語以内が目安) |
| 参考文献 | 角かっこ番号 [1] | 上付き番号。本文の参考文献は50件以内が目安 |
| 図の説明 | 「Fig. 1」(文頭でも省略形) | 図の説明(legend)は300語未満 |
| 表の番号 | TABLE I(ローマ数字、表の上) | 表の上に太字の短い1行タイトル |
| 綴り | 米国式 | 英国式(Oxford English Dictionary) |

### 6.2 どちらを手本にするか

- 卒業論文・国内学会・IEEE 系の国際会議:IEEE の書式を基本にする。電気電子分野の読者に最もなじみがある。
- Nature の書き方から学ぶこと:分野外の読者にもわかるように書く姿勢(要約段落の構成、専門用語を減らす、図を簡潔にする)は、どの論文でも役に立つ。特に要旨と序論の書き方は、Nature の要約段落の構成(7.3節)を参考にするとよい。

### 6.3 投稿先ごとに確認する項目

次の項目は、投稿先によって指定が異なります。共通の数値や形式を決めず、投稿先の最新の規定とテンプレートで確かめます。

| 項目 | 確認する内容 |
|---|---|
| 原稿構成 | 節の順序、見出し、要旨の形式、必須項目 |
| 原稿の長さ | 語数、ページ数、図表数などの制限 |
| 図の形式 | 寸法、文字サイズ、線幅、パネルラベル |
| 画像 | 解像度、形式、加工・生成画像に関する方針 |
| 作成方法 | 使用できるソフト、変換方法、提出形式 |
| 配布条件 | カラー・白黒印刷、オンライン版との違い |
| 引用 | 引用番号、著者名、文献一覧の形式 |
| 提出 | 個別ファイル、補足資料、回答書などの要件 |

## 第7章 論文の各部の書き方

各部の役割をつなぎ、課題・方法・証拠・解釈・結論の間に一貫性を持たせます。以下は標準的な役割分担であり、名称・順序・統合のしかたは投稿先に合わせます。

| 部分 | 主な役割 | 読者が理解すること |
|---|---|---|
| 表題 | 対象と中心的な内容を表す | 何についての研究か |
| 要旨 | 研究の概要を単独で伝える | 何を行い、何がわかったか |
| 序論 | 課題と目的、研究の位置づけを示す | なぜこの研究が必要か |
| 方法 | 対象・条件・手順・仮定を説明する | どのように結果を得たか |
| 結果 | 観測・計算の結果と重要な傾向を示す | どのような事実を得たか |
| 考察 | 結果の意味と限界を論じる | 結果から何が言えるか |
| 結論 | 研究目的への回答をまとめる | 何を新しく明らかにしたか |

執筆の順序は、掲載順と同じでなくてかまいません。主張と図表を先に整理する方法や、書きやすい方法の節から書く方法もあります。途中で論旨が変わったときは、表題・要旨・序論・結論の対応を確かめ直します。

### 7.1 表題(Title)

表題は、検索され、最初に読まれる部分です。

| 規則 | IEEE | Nature |
|---|---|---|
| 内容 | 具体的で簡潔。内容を表すキーワードを入れる | 分野外の人にも何の論文かがわかる程度に一般的で、索引に使える程度に具体的 |
| 長さ | 規定なし(短いほどよい) | 75文字以内 |
| 避けるもの | 「new」「novel」 | 数字、略語、記号 |
| 大文字 | 名詞・動詞・形容詞などの語頭を大文字にする(Title Case)。略語は大文字(DC) | 規定には明記なし。掲載論文の形式に合わせる |

| 悪い例 | 良い例 |
|---|---|
| A Novel Current Control Method | Pole-Zero Cancellation Design of a PI Current Controller for a Brushed DC Motor |
| Study on Motor | Effect of Dead Time on the Output Voltage of a Sign-Magnitude PWM H-Bridge |

書いたら、次を確かめます。

- 研究対象と中心的な内容を読み取れるか。
- 表題が示す内容を、本文が扱っているか(本文より広い範囲を示したり、裏付けのない評価を加えたりしていないか)。
- 不要な語や、曖昧な修飾語がないか。
- 語順、大文字・小文字、略語の扱いが投稿規定に合っているか。

### 7.2 著者と所属

- 研究に実質的に貢献した人だけを著者にする。著者全員が、論文の内容すべてに同意している必要がある。
- Nature では、各著者が何をしたかを「Author contributions」に書く(7.12節)。
- 責任著者(corresponding author)は、出版後の問い合わせに答える人である。
- 投稿の前に、全共著者が原稿を読み、内容と投稿に合意していることを確かめる。改訂のときも、重要な変更は関係する共著者が確認できるようにする。著者資格の基準は、分野と投稿先の方針に従う。

### 7.3 要旨(Abstract)・要約段落(Summary paragraph)

要旨は、本文を読まない人も含めて最も多くの人に読まれます。データベースで検索されるときも、要旨だけが表示されます。

**IEEE の Abstract の規則**

- 1段落、150〜250語。
- それだけで内容がわかるようにする。式・引用番号・脚注を入れない。略語はできるだけ避ける。
- 論文の新しい貢献を明確に書く。
- 3〜5語のキーワードを要旨の中に含める(検索にかかりやすくなる)。

**Nature の要約段落の構成**

Nature の要約段落は、200語以内を目安に、次の4つの部分で書くよう求められています。Nature は構成を注釈した見本を公開しています[B11]。

| 部分 | 内容 | 分量 |
|---|---|---|
| (1) 分野の導入 | 分野外の読者向けの、基本的な導入 | 2〜3文 |
| (2) 背景と動機 | 何がわかっていないか、なぜこの研究をしたか | 1〜2文 |
| (3) 主な結論 | 「Here we show」などで始める | 1〜2文 |
| (4) 意義 | 結果が分野をどう前進させたか | 2〜3文 |

注釈付きの見本[B11]では、さらに細かく、(2) を「関連分野の研究者向けの詳しい背景(2〜3文)」と「この研究が扱う問題(1文)」に分け、(3) の後に「結果が従来の理解とどう違うか(2〜3文)」を置いています。この構成は、IEEE の Abstract を書くときにもそのまま使えます。IEEE では (3) の後に、主な数値結果を入れるとよいでしょう。

**要旨の骨組みの例**(モータ駆動回路を題材にした例。数値は説明のための仮のもの)

> (1) Brushed DC motors remain widely used in small actuators, where the current loop determines the torque response. (2) Pole-zero cancellation is a common design rule for PI current controllers, but its performance under a one-sample computation delay and a duty-ratio limit has rarely been quantified for low-cost microcontrollers. (3) Here we show that the cancellation design keeps the overshoot below 2% up to a crossover frequency of 1/20 of the PWM frequency, whereas the overshoot reaches 15% at 1/10. (4) These results give a simple upper limit on the crossover frequency that can be used without detailed modeling of the delay.

- 卒業論文の要旨:字数は所属の規定に従う。構成は上と同じでよい。
- 背景の説明に語数を使いすぎて、成果がわからない要旨にしない。具体的な成果は、比較対象や数値とともに示す。
- 略語は、要旨だけを読む人にも通じるかを確かめ、必要なら要旨の中で定義する(本文の定義とは別に要る)。

### 7.4 Index Terms・キーワード

- IEEE の論文誌では Index Terms が必須である。アルファベット順に並べ、要旨の最後の段落として置く。
- IEEE は用語集(IEEE Thesaurus)を公開しており、そこから選ぶと検索されやすい。
- 略語は、正式名称の後にかっこで示す(例:pulse-width modulation (PWM))。

### 7.5 序論(Introduction)

序論は、読者を「広い背景」から「この論文の問い」まで導く部分です。次の流れで書きます(漏斗型)。

| 段落 | 内容 | 書き方の注意 |
|---|---|---|
| 1 | 研究分野と、その重要性 | 1〜3文。「近年〜が注目されている」のような決まり文句で始めない |
| 2〜3 | これまでの研究でわかっていること | 文献を引用する。文献を一つずつ紹介するのではなく、考え方の流れでまとめる |
| 4 | まだわかっていないこと(gap) | 序論の中心。「しかし〜は明らかになっていない」 |
| 5 | 本研究の目的と方法 | gap に対する答えとして書く |
| 6 | 本研究の貢献 | 電気電子分野の論文では、貢献を箇条書きにすることが多い |
| 7 | 論文の構成 | IEEE の論文では「The rest of this paper is organized as follows. Section II describes …」のように書くことが多い |

序論には、著者が研究を進めた時系列(「最初に〜を試し、次に〜を試した」)をそのまま書きません。読み手が理解しやすい順(背景→現状→限界→目的)に組み直します。課題・新規性の整理は5.4節に示しました。

| 悪い例(文献の羅列) | 良い例(流れでまとめる) |
|---|---|
| A らは PI 制御を提案した[1]。B らは PI 制御を改良した[2]。C らはデッドタイムを補償した[3]。 | 電流制御には、構成が簡単な PI 制御が広く使われている[1], [2]。PI ゲインは極零相殺で設計されることが多いが、この設計は計算の遅れを考慮していない[2]。デッドタイムの影響は補償法として研究されてきた[3]ものの、遅れとデッドタイムが同時にあるときの応答は定量的に示されていない。 |

「〜は研究されていない」と断定するときは、調べた範囲と根拠を確かめます(9.5節)。

**序論の書き方の改善例**(題材は 8.1 節の図の説明と同じ。数値は説明用の仮のもの)

- 改善前:モータ制御は重要である。本研究では、さまざまな条件で電流制御の実験を行った。
- 改善後:従来の設計では、計算の遅れがあるときの電流ステップ応答の行き過ぎが、交差周波数ごとに示されていない。本研究では、PWM周波数と負荷を固定して交差周波数だけを変え、行き過ぎへの影響を調べる。

改善のポイント:

- 「制御」という広い言葉を、「行き過ぎ」という評価対象に具体化した。
- 未解決の課題と、研究の目的を対応させた。
- 何を変え、何を固定するかを示した。
- 実際の原稿では、先行研究に関する記述に出典を添える。

### 7.6 方法(Methods / Experimental Setup)

方法は、他の研究者が同じ結果を再現できるように書きます。これは IEEE でも Nature でも同じです。

- 装置の構成図(ブロック図)と、主要な部品・測定器の型番を示す。
- 実験条件は表にまとめるとよい(電源電圧、PWM周波数、デッドタイム、制御周期、ゲインなど)。
- 自作のプログラムは、アルゴリズムを示し、可能ならコードを公開する。
- 既に発表された方法は、詳しく繰り返さず引用する。変更した点だけを書く(Nature の規定)。
- 統計処理(測定回数、平均、標準偏差、誤差棒の意味)を明記する。Nature では、図の誤差棒と統計の定義を図の説明に書くことが求められている。
- Nature では、Methods を短い太字の小見出しで区切る。
- 手順を圧縮しすぎて、どの操作をどの順に行ったかがわからなくならないようにする。逆に、結果に関係しない説明で主要な条件を埋もれさせない。

理論や数値計算を使うときは、次も書きます。

- モデル、主な仮定、パラメータ、計算条件、評価の方法。
- 検証に使った条件が、モデルの仮定の適用範囲に入っているか。
- 既存のモデルの説明と、本研究で追加・変更した部分の区別。
- 結果に影響するときは、初期条件・境界条件、離散化、収束の条件。

### 7.7 結果(Results)

- 事実を図表と文章で示す。
- 図は、主張が伝わる順に並べる。最初に引用する順番と図の番号を一致させる(IEEE の規定)。
- 一つの段落の最初の文で、その段落で示すこと(主張)を書く。
- 方法に書いた評価指標と対応させ、比較の条件がそろっているかを確かめる。
- 主張に有利な結果だけを選ばない。解釈に必要な不利な結果や例外も書く。
- 「結果と考察」を一つの節にまとめる場合も、観測した事実を先に書き、解釈と区別する。

### 7.8 考察(Discussion)

論文では次のことを必ず書きます。

- 先行研究との比較:何が同じで、何が違うか。違う場合はその理由。
- 新規性の確認:序論で挙げた gap に、結果がどう答えたか。
- 限界:結果が成り立つ条件の範囲。確かめていないこと。
- 意義と今後:結果が分野にどう役立つか。

書いたことを、事実・解釈・限界に分けて確かめます(第1章)。

| 区分 | 書く内容 | 例 |
|---|---|---|
| 事実 | 観測・計算で得た結果 | 同じ測定条件で、行き過ぎが 15% から 2% 未満に減った |
| 解釈 | 事実に基づく意味や原因の検討 | 計算の遅れの影響が小さくなったためと考えられる |
| 限界 | 今の証拠では確かめられていない範囲 | 他のモータや負荷では確かめていない |

**考察の書き方の改善例**(数値は説明用の仮のもの)

- 改善前:ゲインを調整して性能が大幅に向上した。この方法はすべてのモータで有効である。
- 改善後:同じ装置・同じ測定条件で、交差周波数を PWM 周波数の 1/10 から 1/20 にすると、行き過ぎは 15% から 2% 未満に減った。今回の条件では、計算の遅れの影響が小さくなったためと考えられる。他のモータや負荷での有効性は、追加の測定が必要である。

改善のポイント:

- 改善を評価した量と数値を示した。
- 比較が同じ測定条件であることを明示した。
- 観測した事実と、原因についての解釈を分けた。
- 確かめていない条件への一般化を避け、限界を書いた。
- 実際の原稿では、測定回数やばらつきと対応させる。数値の差だけで、原因や統計的な確かさが証明されるわけではない。

### 7.9 結論(Conclusion)

- IEEE のガイドでは、結論で研究の広い意義と今後の方向を示し、結果を誇張しないことが求められている。
- 要旨の繰り返しにしない。要旨は「何をしたか」、結論は「何がわかり、それが何を意味するか」に重点を置く。
- 新しいデータや、本文にない主張を入れない。
- 今後の課題は、今回確かめた内容と区別して書く。将来の期待が、今の成果のように読める書き方を避ける。

### 7.10 付録(Appendix)

本文の流れを妨げる長い導出、補足的なデータは付録に移します。IEEE では「Appendix A」のように番号を付けます。Nature では、補足の図表を Extended Data や Supplementary Information として別に出します。

### 7.11 謝辞(Acknowledgment)

- 研究費の提供元、装置や試料を提供した人、助言をくれた人に謝意を示す。
- Nature の規定では、簡潔に書き、「excellent assistance」のような大げさな形容詞を使わない。匿名の査読者への謝辞は書かない。

### 7.12 データ・コードの公開と各種の宣言

近年の論文誌では、本文の後に次のような宣言を書くことが求められます。Nature ではいずれも必須です。

| 宣言 | 内容 |
|---|---|
| Data availability | データをどこで入手できるか(リポジトリと Digital Object Identifier(DOI)など) |
| Code availability | 解析・制御に使ったプログラムをどこで入手できるか |
| Author contributions | 各著者が何をしたか(イニシャルで書く) |
| Competing interests | 利益相反の有無 |
| Funding | 研究費の提供元 |

卒業研究でも、測定データと解析プログラムを研究室のルールに従って保存し、論文から追跡できるようにしておきます。

## 第8章 図・表・式・引用の書式

第3章の図表のルールに加えて、論文では投稿先の細かい書式に従います。

### 8.1 図

| 項目 | IEEE | Nature |
|---|---|---|
| 本文での引用 | 「Fig. 1」。文頭でも省略形を使う。「Fig. 1(a) and 1(b)」でも Fig. は単数 | 図の番号で引用する(掲載論文の形式に合わせる) |
| キャプション・説明 | 「Fig. 1.」の後に説明。最初の語は大文字。「A」「The」で始めない。例:「Fig. 1. Experimental setup. (a) Block diagram. (b) Photograph.」 | 図全体の短いタイトルの後に、各パネルと記号の説明。Methods がある場合は方法の詳細を書かない。300語未満 |
| パネルのラベル | (a)、(b) | 小文字の a、b(掲載論文の形式に合わせる) |
| 図の大きさ | 1段幅または2段幅 | 1段 90 mm、2段 180 mm、高さは最大 170 mm |
| 図の中の文字 | 軸には記号だけでなく量の名前と単位を書く(第3章) | 先頭だけ大文字、ピリオドなし。数値と単位の間に空白。記号の凡例は、できれば図の中ではなく図の説明に書く |
| 番号の順番 | 最初に引用した順に番号を付ける | 同じ |

本文での引用のしかたは、3.2節の考え方がそのまま当てはまります。英語でも「(Fig. 3)」を文末に添えるだけでなく、「As shown in Fig. 3, the ripple decreases in inverse proportion to the PWM frequency.」のように、図から何がわかるかを文で述べます。

**図表の役割を確かめる**:図表ごとに、(1) 何を示す図表か、(2) 読者が読み取るべき重要な事実は何か、(3) その事実が論文の主張とどう関係するか、を説明できるようにします。図と表で同じ情報を重ねるときは、役割の違いがあるかを確かめます。

**図の保存形式**

- 線画や文字を含む図は、投稿先が受け付けるベクター形式を検討する。
- 写真などは、最終的な掲載サイズに対して十分な画質にする。低画質の画像の画素数を増やしても、失われた情報は戻らない。

**図の説明(キャプション)に書くこと**:本文を読み返さなくても図の内容がわかるように書きます。必要に応じて、次を含めます。

- 示している対象と変数。
- 図を理解するために必要な条件。
- パネル、記号、線種、略語の意味。
- 試料数や測定回数(何を数えた値かがわかるように。試料数と繰り返し測定の回数は意味が違う)。
- 誤差棒が、標準偏差・標準誤差・信頼区間のどれを示すか。
- 統計的な記号を使うときは、その意味と検定の方法。

**図の説明の改善例**(IEEE 形式。数値は説明用の仮のもので、対応する実測図はない)

- 改善前:`Fig. 2. Experimental results. Error bars show variation.`
- 改善後:`Fig. 2. Current ripple versus PWM frequency. The duty ratio was fixed at 0.5. Each point is the mean of five measurements, and the error bars indicate the standard deviation.`

改善のポイント:

- 図が示す変数と関係を明示した。
- 固定した条件(デューティ比)を示した。
- 測定回数と、点が平均値であることを示した。
- 誤差棒が表す統計量を定義した。

### 8.2 表

| 項目 | IEEE | Nature |
|---|---|---|
| 番号 | 「TABLE I」(ローマ数字)。表の上の中央 | 表の上に太字の短い1行タイトル |
| タイトル | 番号の下に説明。末尾にピリオドを付けない | 短い1行 |
| 注 | 表の下に脚注 | 記号と略語の定義を表のすぐ下に書く |

### 8.3 式

- 式の番号は、行の右端にかっこで付ける:(1)、(2)。
- IEEE では、本文で式を参照するときは番号だけを書く:「from (1)」「substituting (2) into (3)」。文頭だけ「Equation (1) shows …」と書く。
- 式の後の文章も文の一部である。式が文の終わりにくるときはピリオドを付ける。
- 変数はイタリック、単位・関数名・数字は立体(2.4節)。
- 変数、定数、添字の意味を定義する。単位と記号は、原稿の全体で統一する。
- 式の導出や変形に必要な仮定を示し、読者が導出を追えるようにする。

### 8.4 章・節の参照

- IEEE では章を「Section II」、節を「Section II-A」のように書く。「Subsection」という語は使わない。
- 日本語の卒業論文では「第2章」「2.1節」と書く。

### 8.5 参考文献

**IEEE 形式**:番号は、本文で最初に引用した順に付けます。本文では角かっこの番号で引用します:「… as reported in [3].」「[1], [2]」「[4]–[7]」。

```text
[1] A. B. Author, C. D. Author, and E. F. Author, "Title of article," Abbrev. Title of Periodical, vol. x, no. x, pp. xxx–xxx, Abbrev. Month year, doi: xx.xxxx/xxxxxx.
[2] A. B. Author, Title of Book, xth ed. City, Country: Publisher, year, pp. xxx–xxx.
[3] A. B. Author, "Title of paper," in Proc. Abbrev. Name of Conf., City, Country, year, pp. xxx–xxx.
```

- 文献の特定の図や式を引用するときは、「in Fig. 2 of [1]」ではなく「[1, Fig. 2]」、「[1, eq. (8)]」、「[1, Sec. IV]」と書く(IEEE の規定)。
- 著者が多い場合は、筆頭著者の後に「et al.」と書く(何人から省略するかは IEEE の Reference Guide を確認する)。

**Nature 形式**

- 本文では上付きの番号で引用する(例:…is widely used¹⁻³.)。
- 文献一覧では、著者は「姓, イニシャル」。著者が5人を超える場合は、筆頭著者の後に「et al.」。論文の題名は立体で、雑誌名は斜体の略称、巻は太字。
- 出版済み・受理済みの論文、認められたプレプリントサーバ(arXiv など)の論文は引用してよい。「投稿準備中」の論文は文献一覧に入れない。

**どちらの形式でも**

- 文献管理ソフト(Zotero、Mendeley、BibTeX など)を使うと、形式の切り替えと番号の付け直しが確実になる。
- 自分の既発表の研究も適切に引用し、新しい原稿で加えた内容を示す。
- 本文の引用と参考文献の一覧が対応しているか、書誌情報が正しいかを確かめる。
- 引用した文献は、自分で読んで内容を確かめる。孫引き(他の論文に引用されていた文献を、読まずに引用すること)はしない。

## 第9章 英語で論文を書く

### 9.1 基本の方針

- 日本語で完成させてから翻訳するより、最初から英語の構成と表現で書くほうがよいとされる。
- 手本の論文を決め、よく使われる表現を学ぶ。ただし、文章を丸ごと写すのは盗用である。
- Nature は、英語を母語としない読者にもわかるよう、明快で簡潔に書くことを求めている。専門用語と略語は最小限にし、使うときは説明する。

### 9.2 時制と態

| 内容 | 時制 | 例 |
|---|---|---|
| 確立した知識・一般的な事実 | 現在形 | The back-electromotive force (EMF) is proportional to the rotational speed. |
| 先行研究の内容 | 過去形または現在完了形 | Smith et al. proposed … / Several studies have reported … |
| 自分が行った実験と結果 | 過去形 | We measured the current ripple at four PWM frequencies. |
| 図表が示していること | 現在形 | Fig. 3 shows that … |
| 結論・解釈 | 現在形 | These results indicate that … |

「we」を主語にした能動態は、IEEE でも Nature でも広く使われています(Nature の要約段落の「Here we show」など)。受動態ばかりにすると、誰が何をしたのかがわかりにくくなります。

### 9.3 読みやすい英文

- 読み手は、文の最初に既に知っている情報(話題)を、文の最後に新しい情報や強調したい情報を期待する。この順に並べる[B3]。
- 主語と動詞を近づける。主語の後に長い修飾句を入れない[B3]。
- 一文に一つの内容。長い文は分ける。
- 提出前に、語順、主語と動詞の一致、単数・複数、冠詞、指示語、時制を確かめる。
- 先行研究の成果と自分の成果は、主語や引用で区別する。
- 自動の校正ツールは確認の補助に使い、内容や論理の判断を任せきりにしない。

### 9.4 IEEE の文法・表記の規則(抜粋)

| 規則 | 例 |
|---|---|
| 3つ以上を並べるときは、and の前にもコンマ | voltage, current, and power |
| 名詞を修飾する複合語はハイフンでつなぐ | a high-frequency signal、a second-order system |
| 述語になる場合はハイフンを付けない | The system is second order. |
| 制限用法は that、非制限用法は which(コンマで区切る) | The method that we propose … / The PI controller, which is widely used, … |
| 略語・数字の複数形にアポストロフィを付けない | FETs、1980s |
| 単位の記号は SI に従う | μs、kHz、mΩ(u で μ を代用しない) |

### 9.5 誇張しない

- 「novel」「first」「unprecedented」のような語は、根拠がない限り使わない。「first」と書くなら、先行研究を十分に調べている必要がある。
- 根拠の強さに合わせて書く:demonstrate(示した) > indicate(示している) > suggest(示唆する) > may(可能性がある)。

### 9.6 英文校閲

文法の誤りが多い原稿は、内容を審査される前に不採録になることがあります。投稿前に、指導教員や英文校閲を通します。Nature は、言語の問題だけで不採録にすることはないとしつつ、校閲サービスの利用を勧めています。

## 第10章 投稿から採録まで

### 10.1 投稿の前に

- 投稿先の規定(著者向けガイド)を最初に読み、その論文誌に載っている論文を1本手本にする。規定に従っていない原稿は、内容を審査される前に返却されることがある。
- IEEE は論文誌ごとに LaTeX と Word のテンプレートを用意している。最初からテンプレートで書く。
- Nature は、査読用の原稿に行番号を付けるよう求めている。査読者が指摘する場所を示しやすくするためである。
- 共著者全員が原稿の内容に同意していることを確認する。

推敲は、内容の確認と投稿形式の確認を分けて行います。自分で時間を置いて読み直すほか、第三者に、説明不足や論理の飛躍を指摘してもらいます。英文校閲を使う場合も、内容と主張の妥当性は著者が確かめます。次の順に確かめるとよいでしょう。

1. 研究の目的と主張、それを支える証拠の対応。
2. 各部の役割と、序論・結論の一致。
3. 方法、条件、図表、式、引用の説明不足。
4. 文章、用語、英文、数値の整合。
5. 投稿規定、テンプレート、提出ファイル、共著者の合意。

### 10.2 カバーレター

投稿のときに、編集者あての短い手紙(カバーレター)を添えます。

- 論文の題名と種類
- 何が新しいか、なぜその論文誌の読者にとって重要か(2〜3文)
- 他の論文誌に投稿していないこと
- 利益相反の有無

Nature への事前の問い合わせ(presubmission enquiry)でも、幅広い読者にとっての重要性を述べた段落が求められます。

### 10.3 査読への対応

投稿した論文は、専門家による査読を受け、「採録」「修正のうえ採録(minor / major revision)」「不採録」などの判定を受けます。修正を求められた場合は、回答書(response letter)を書きます。

**回答書の構成**

1. 査読者と編集者への謝意(短く)
2. 主な変更点の要約
3. 指摘の一つ一つへの回答。指摘をそのまま引用し、その下に回答と、本文のどこをどう直したか(ページ・行)を書く

**指摘の分類と回答の型**:指摘は、まず種類を分けてから、対応を決めます。

| 種類 | 例 | 主な対応 |
|---|---|---|
| 修正要求 | 図の軸に単位がない | 直して、箇所を示す |
| 質問 | 測定は何回行ったか | 答え、必要なら本文に書き足す |
| 根拠の要求 | 結論を支えるデータが足りない | データを示す。ないなら主張を弱める |
| 説明不足・構成 | 方法の手順がわからない／順序が読みにくい | 書き足す・並べ替える |
| 表現 | 曖昧な語、用語の不統一 | 数値や用語に直す |
| 誤解 | 査読者が意図と違う意味に読んだ | 誤解を生んだ書き方を直し、意図を説明する |
| 規定 | 書式の規定に合っていない | 規定に合わせる |
| 対応が難しい | 追加実験の装置がない | できない理由と、代わりにしたことを書く |

回答は、次のいずれかの型で書きます。まず指摘の意図を一文で受け止め、そのうえで答えます。

- 修正した場合:「ご指摘のとおり、〔内容〕を〔箇所〕で〔どう〕修正した。」
- 一部修正した場合:「〔修正した部分〕は、ご指摘に従って修正した。〔修正していない部分〕は、〔理由〕のため、〔代わりの対応〕とした。」
- 修正しない場合:「ご指摘の〔意図〕は重要と考える。一方、〔根拠〕のため、〔対象の範囲〕では原稿の記述が妥当と考え、修正しなかった。誤解を避けるため、〔箇所〕に〔補足〕を加えた。」

指摘に反論するときも、指摘の意図を否定しません。根拠(データ・文献・条件)と、反論が当てはまる範囲を示します。

注意:

- 回答書に書いた内容は、必ず本文にも反映する。
- 修正箇所がわかる版(変更箇所に色を付けた版)を添える。
- 指摘が誤っていると考える場合は、根拠を示して丁寧に説明してよい。
- 査読者は「読者の代表」であり、査読の目的は論文をよりよくすることである。

再提出の前に、次を確かめます。

- すべての指摘に回答したか。
- 回答の内容と、改訂した原稿が一致しているか。
- 修正箇所を、読者が特定できるか。
- 修正によって、他の節・図表・要旨・結論と矛盾していないか。
- 共著者が、改訂の内容を確認したか。

### 10.4 研究倫理(論文で特に注意すること)

4.3節に加えて、次の点に注意します。

- **二重投稿**:同じ内容を複数の論文誌に同時に投稿しない。国際会議で発表した内容を論文誌に投稿する場合は、投稿先の規定を確認し、違いを明示する。
- **画像の加工**:Nature などは画像の加工について規定を設けている。オシロスコープの画面や写真の一部だけを消す・強調するといった加工はしない。明るさの調整などは、画像全体に一様に行い、その旨を書く。原画像と処理の内容は保管し、確認を求められたときに示せるようにする。
- **図の再利用**:他の論文の図を使う場合は、著作権者の許可が必要である。自分の過去の論文の図でも、出版社に著作権がある場合がある。
- **著者資格**:研究に実質的に貢献していない人を著者に入れない。貢献した人を外さない。

### 10.5 卒業論文の場合

- 書式(ページ数、要旨の字数、章立て、提出形式)は所属の規定に従う。
- 構成と書き方は、第7章と同じでよい。卒業論文はページ数の制約が緩いので、方法と結果を詳しく書き、後輩が研究を引き継げるようにする。
- 指導教員に見せる前に、実験レポート用のセルフチェックと、第7・8章の書式を確認する。

### 10.6 投稿前チェックリスト

**研究内容と論理**

- [ ] 未解決の課題と研究の目的を明確にした。
- [ ] 先行研究と本研究の違いを示した。
- [ ] 主要な主張に対応する証拠を示した。
- [ ] 序論の目的に、結論が答えている。
- [ ] 事実と解釈を区別した。
- [ ] 不確かさ、限界、適用範囲を説明した。
- [ ] 確かめていない条件へ、一般化しすぎていない。

**方法と表現**

- [ ] 対象、条件、手順、仮定、評価の方法を説明した。
- [ ] 変数、定数、添字、単位を定義した。
- [ ] 既存の方法と、変更した点を区別した。
- [ ] 段落と文の論理のつながりを確かめた。
- [ ] 用語、略語、記号、数値の表記を統一した。
- [ ] 英文の語順、文法、時制を確かめた。

**図表と引用**

- [ ] 各図表を本文で参照し、重要な事実を説明した。
- [ ] 軸、単位、凡例、パネルのラベルを確かめた。
- [ ] 図の説明に、条件、略語、記号の意味を書いた。
- [ ] 試料数と、誤差棒の意味を説明した。
- [ ] 最終的な掲載サイズで、図表を読める。
- [ ] 色以外でも、系列を識別できる。
- [ ] 表を編集できる形式にし、数値の桁数と位置をそろえた。
- [ ] 画像の加工、転載、改変の扱いを確かめた。
- [ ] 本文の引用と、参考文献の一覧が対応している。

**投稿と改訂**

- [ ] 全共著者が原稿を確認し、投稿に合意した。
- [ ] 第三者の確認や推敲を行った。
- [ ] 投稿先の最新の規定とテンプレートを確認した。
- [ ] 必要な提出ファイルを用意した。
- [ ] 改訂では、すべての指摘に回答した。
- [ ] 回答書と本文の修正内容が一致している。
